# Rust port support ledger

The Rust binary is **2.0.0-alpha.1 and incomplete**. The retained TypeScript implementation is the behavioral oracle. npm remains 1.36.0; npm entrypoints, shell installers, stable release packaging, and TypeScript source remain unchanged. Rust binaries do not invoke TypeScript.

The complete parser inventory is [contracts/cli-commands.json](../contracts/cli-commands.json). Help registration does not imply implementation. Unsupported commands and policies fail nonzero; some alpha rejection and partial-failure envelopes intentionally differ from the source.

## Implemented scope

- **Discovery and list:** Configured primary/child and existing linked discovery; standalone discovery; ordinary Git `list` and `list --json` without `.worktrees`. Ordinary fallback applies only to list and does not enable standalone mutation. Configured/ordinary and standalone list shapes remain distinct. Verbose/table/depth options and bare topology remain unsupported.

- **Configured init:** Primary non-bare root; repository discovery or `--no-discover`; custom contained repos/worktrees directories; dry-run; source-identical config and platform hook-example bytes; local managed-ignore planning/application. Existing configuration reports the source error. Force, ignore-scope preferences/migration, stale owned ignore rules, non-Git bootstrap, linked/bare init and external paths remain unsupported.

- **Configured clone (bounded local-file slice):** `clone --all --json` from the ordinary configured primary checkout clones every missing direct `reposDir/<repository-name>` child from canonical absolute filesystem paths or plain absolute `file://` URLs. Remote-default checkout, `--base`, repository/workspace configured bases, and repeatable `--repo-base` overrides are supported; selected repositories are fully preflighted before managed-ignore or clone mutation. Complete success JSON, clone ordering, checked-out branches, and filesystem effects match retained-source disposable fixtures.

  Network/authenticated/SCP and relative transports, interactive or human mode, coordinated/linked/bare topology, external/custom child paths, absent repository directories, non-canonical/symlinked remotes, shallow/alternate/replace/graft/promisor remotes, non-alphanumeric ASCII or portable-case-colliding repository names, and executable Git transport/filter/template/environment projections fail closed before mutation. Clone work is staged under the ignored repositories directory, remote/config/destination identity is revalidated before publication, and pre-publication failure rolls back managed-ignore bytes and staging state. Arbitrary concurrent replacement, post-publication rename failure recovery, source partial-failure envelopes, URL repair/protocol conversion, unmanaged-local reconciliation, broader topology and complete error parity remain unsupported.

- **Configured create:** Meta root and discovered children, selected-child-only creation, configured child paths and identities; `--only`/`--group`; default/branch/repo-branch naming and preserved/flattened slashes; local/default/explicit base resolution, configured workspace/repository bases and `--repo-base`; dry-run for conflict-free plans; explicit local branch reuse with `--conflict REUSE_EXISTING`; dirty-workspace guidance. Requires explicit `--no-launch --no-switch`. Configured POSIX file lifecycle hooks are supported in JSON mode; `--no-hooks` explicitly bypasses them. Bounded primary-source materialization, exact managed-destination reuse and local-file-origin remote-only conflicts are supported as detailed below. Other existing destinations, checked-out targets elsewhere, broader remote conflicts, other branch-only conflict dry-run and automatic path-length fitting remain unsupported.

- **Configured create remote-only conflicts (local macOS acceptance):** With `--json --no-hooks --no-launch --no-switch`, explicit `REUSE_EXISTING` creates the requested branch from the local main-base OID, without an upstream; it does not adopt the remote target OID. Explicit `ABORT` returns the source failure envelope without mutation. Dry-run preserves all files/refs and reports blocking ABORT or non-blocking REUSE_EXISTING conflicts; source JSON dry-run exits 0 even for a blocked plan. Complete source/native JSON, selected-child/group/order, mixed new repositories and pre-existing local branches, worktree bytes, refs and upstream effects are covered in `tests/rust/create_remote.rs`.

  This subset requires managed paths to be already ignored, ordinary POSIX primary repositories on `main`, target base OIDs equal to local `main`, no other registered worktrees, and a separate ordinary bare origin addressed by an absolute filesystem path. Origin HEAD must be `main`; the requested remote head and existing loose remote-tracking ref must agree, and the tracking ref must name an available local commit. Availability is checked only after preflight; dangling object references reject without fetch. Bare-origin validation enumerates the exact head name, OID, object type and symbolic target; it requires an ordinary commit ref and repeats these checks on every revalidation. Revision-name fallback and tag peeling cannot supply a missing head, including tags named `refs/heads/<branch>`. Within remote-scope creation, local head existence/OIDs, local base resolution and revalidation, completed targets and branch rollback ownership also use exact ref names; a local tag with that spelling neither creates a branch conflict nor supplies a disappeared head. Requested bases resolve exclusively from exact local heads in this scope, including repositories whose target branch already exists; remote-only bases and remote-namespace tag shadows are rejected. Every explicit requested base retains its exact ref and OID independently of the target source, including pre-existing target branches; this requested identity is revalidated before mutations and final actual/dry-run success even after that item completes. Deletion, change or a same-OID shadow tag invalidates the plan. Every new branch in remote scope starts from the validated OID, including default/legacy-omitted bases; mutation never re-resolves a movable base name or shadow tag. No transport or fetch runs. The conflict subset allows only ordinary core repository/filemode/log/case settings, user identity, commit signing preference, maintenance.auto, and the default origin URL/fetch mapping. Other Git configuration, transport environment overrides, network/file-URL syntax, non-origin/multiple remotes, remote bases, missing/stale tracking refs, symbolic target refs, Windows, dirty/protected/occupied targets, hooks, filters/fsmonitor, gitlinks, alternate/shallow/promisor Git topology, existing destination reuse and materialization combinations reject before mutation. Mixed selections preflight every selected primary’s configuration and topology before default/explicit base resolution or remote object inspection, including ABORT and dry-run. Conflict evidence uses exact ref names and ordinary loose-ref metadata without rev-parse or object peeling; nested prefix directories are not exact refs. A shorter ordinary loose ref that blocks a nested pathname is also not an exact conflict; exact packed-name enumeration still runs. Malformed or symlinked blocking ancestors fail closed. Packed exact refs are recognized, while packed tracking and malformed/dangling/symbolic entries remain outside the accepted loose-tracking subset. A discoverable local transport canary with a positive control verifies that missing promisor base objects never trigger native transport or mutation in this scope. Remote eligibility restrictions apply only after finding a target tracking ref for origin/another configured remote, or an exact target head in an observable local bare origin. Conflict-free HTTPS, multiple-remote and other remote configurations retain the existing local create path without native transport; local-origin absent targets and tracked main branches are covered too. Broader source policy remains unsupported: the retained source can resolve a remote base and establish upstream tracking, and human ABORT/dry-run exit codes differ from JSON.

  Primary directory/Git metadata, base and remote/tracking OIDs, and every newly created worktree’s target OID, reciprocal registration, lock/protection state and filesystem identity are revalidated around mutation and before success, including mixed selections. Dry-run revalidates its plan without mutation, including every pending destination’s entry occupancy, ordinary safe ancestors, exact local branch state and authoritative primary-only Git registration. The same pending checks run before actual mutation; files, directories, dangling links and added/relocated registrations invalidate the plan while caller-owned entries are preserved. Changed tracking refs roll back only newly owned branches/worktrees and preserve pre-existing local branches. Changed or unproven ownership preserves that worktree and any containing ancestor for recovery; independently still-owned siblings and branches roll back. These checks do not establish atomic protection against arbitrary concurrent replacement or complete source failure/recovery parity. Reproducible source characterization, RED/GREEN logs, validation and frozen hashes are under `target/create-remote-only/`. Companion Rust documentation needs this bounded scope before publication; companion repositories were not edited.

- **Configured create exact destination reuse (local macOS acceptance):** `--conflict REUSE_EXISTING --no-hooks --no-launch --no-switch` accepts clean, unlocked, non-prunable linked worktrees at the exact configured destination, belonging to the selected primary repository and requested local branch. Existing branches without an exact reusable destination still reject conflict dry-run.

A deterministic mid-create destination replacement is detected; sibling rollback preserves the replaced worktree. A changed reused ancestor conservatively retains the transaction for recovery. This does not establish atomic protection against arbitrary external filesystem/ref replacement, complete source recovery/error precedence, remote-backed reuse, active reuse lifecycle/materialization, or whole-port completion. Existing materialization/lifecycle gates remain intact.

- **Configured create materialization (local macOS acceptance):** Direct repository `copy` arrays copy regular files and directory trees; POSIX `symlink` arrays create native absolute links to regular primary-checkout sources. Entries run in copy-then-link declaration order. Missing sources are visible optional skips. Conflict-free dry-run plans, successful JSON envelopes (including `repositoryResults`) and target-tree blocking envelopes match retained source fixtures. Selected-child-only and full-workspace creation are covered. Repository pre-create runs before refreshed materialization planning/execution; repository post-create runs afterward. `--no-hooks` does not disable materialization. Source bytes and file/directory permissions are preserved in the tested ordinary permission cases.

  Planning rejects source symlinks (including nested/broken/escaping links), special files, nested Git sources, overlapping policies, non-ASCII materialization names and inspected target-tree names, and portable ASCII case collisions. Materialization combined with existing worktree destination reuse, and linked/bare source projection, remain unsupported. Target-tree, filesystem occupancy and destination-filesystem POSIX link capability checks precede hooks/managed-ignore writes, then repeat after workspace/repository pre-hooks. Link probes use exclusive private directories at the nearest existing destination ancestor and remove only recorded owned entries; cleanup failures block creation. This is bounded fail-closed support, not complete source materialization topology or error parity.

  Exclusive file creation records successful write prefixes for partial-write recovery. Cleanup checks object identity and copied bytes/link targets, removes only owned empty directories, and preserves changed copies. Retained owned directories regain their recorded copied permissions after cleanup, children first; restoration failures are reported. POSIX restoration verifies device/inode on the opened directory and changes permissions through its handle (no-follow opens on macOS/Linux). Changed/locked Git ownership and nested repositories are checked before materialization cleanup; any materialization recovery failure conservatively retains the coordinated worktrees. Tests cover a real file-size-limit failure, read-only directory cleanup, hook-written destination symlinks, changed copies, existing branches, and hook commits. Recovery uses the native coordinated failure envelope; complete source recovery outcomes, arbitrary concurrent path/ref replacement, platform-specific identity semantics, capability changes after the last probe, and arbitrary concurrent filesystem replacement remain unclaimed. Remove/doctor/exec/setup still reject nonempty materialization policies; this create slice does not implement those consumers.

## Mutation safety and remaining parity work

Plans check Git identity, branch/ref state, destinations, config and effective ignore policy before execution. Coordinated create records newly created branches before adding worktrees. Rollback removes worktrees through Git, preserves pre-existing branches, checks ownership before cleanup, and reports cleanup failures. File rollback preserves files changed after the transaction wrote them. Directory cleanup is limited to owned empty directories; production Rust does not recursively delete Git repositories.

This is not full failure parity. Coordinated mid-execution failures return nonzero alpha envelopes containing completed operations and rollback errors, rather than the complete source recovery contract. Concurrent external Git changes in the final validation-to-mutation window, partial filesystem writes, and complex mixed repository failures need more characterization. Complete hook recovery envelopes, broader materialization recovery parity, configuration migrations, Unicode collision rules, stale ignore reconciliation, external/symlinked paths and bare/linked mutation topology remain blocking work.

Still unported: add/delete, pull/push/sync, move, switch terminal/editor launchers, configure editing, update/uninstall and native distribution integration. Broader shell startup-file policies outside the bounded subset above remain unported. Clone support is limited to the bounded local-file slice above. Human init/create/remove text is not source-identical; status parity is bounded to the captured-process cases above. Full parser/help/error precedence is not claimed. Remaining hook and materialization policies require their real lifecycle, provenance, input, timeout and recovery contracts; empty success results are not substitutes.

Relevant source contracts: [configuration](../src/lib/config.ts), [create](../src/commands/create.ts), [remove](../src/commands/remove.ts), [managed ignore](../src/lib/managed-ignore.ts), [hooks](../src/lib/hooks.ts), [JSON envelopes](../src/lib/json-output.ts), [executable distribution](../contracts/executable-distribution.json). Downstream arashi-docs/arashi-skills need updates before publishing these workflows; they are outside this authorized child worktree and were not modified.
